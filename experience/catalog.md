## 教训（3/120）

- **arch-html-inline-style**：架构等审阅页不要写内联 style：校验器把多个内联样式拼接后按 font 声明检查，会把 margin、padding 误判为字号；数据字段名避开 更新时间、生成时间、SHA-256、示例数据 等被 check_document 拦截的元数据词（008 会话架构页首次校验失败）　确认 1 次，最近 2026-10-28
- **reuse-knowledge-only-sources**：experience.py reuse 遇到只有 Luz-Crawl 原始路径、没有会话快照的来源（如 SRC-078/079/106）会中断整批，复用前先确认 snapshot 带 session 字段，并分小批复用（008 会话复用时 KeyError session）　确认 1 次，最近 2026-10-28
- **规范页技术记号**：规范页正文用中文，99+、Esc、YYYY-MM-DD 等技术记号放进 code 或 kbd 元素；“不要字母”指的是不用文字头像，不是页面里禁止一切拉丁字母（用户澄清，validate_skill.py 已改为只放行 code 与 kbd）　确认 1 次，最近 2026-10-28

## 设计理念

### PAT-036 健身房会员系统：卡—脸—门
- 适用：小程序、后台；行业：健身房；使用 1 次，最近 2026-10-26
- 要点：会员的核心路径是买卡 → 录脸 → 刷脸进门；首页先回答“我的卡还能不能用、脸录了没有”，其余入口放在宫格
- 首页顺序：会员卡卡片（剩余次数或到期） → 人脸状态条 → 快捷入口 → 热门会员卡
- 后台核心：用户（卡与人脸状态）、套餐（上下架）、订单（退款）、核验记录（未通过原因）
- 依据：[健身俱乐部管理系统开源项目](https://github.com/small-bears/gyms)

### PAT-037 一页一个重点，流程中不插营销
- 适用：小程序；行业：通用；使用 1 次，最近 2026-10-26
- 要点：每页一个主行动；购卡、支付、录脸流程中不出现抽奖、推荐等目标流程以外的内容
- 依据：[微信小程序设计指南](https://developers.weixin.qq.com/miniprogram/design/)

### PAT-038 三合一系统设计页
- 适用：网页；行业：通用；使用 1 次，最近 2026-10-26
- 要点：系统功能列表 + 可操作小程序 + 后台；两端共享演示数据，原型控制放在界面外侧
- 编号：功能、页面、动作编号来自同一份规格，与架构一致
- 验证：浏览器走通主流程、无脚本报错后再发布终版

### PAT-041 小程序页面功能隔离
- 适用：小程序；行业：通用；使用 1 次，最近 2026-10-26
- 要点：首页只放门店、商品、营销；会员卡状态、订单、记录、人脸、持有的券只放“我的”
- 来源：用户反馈：首页出现我的信息与使用记录是错误的

### PAT-044 主题色系统先于页面
- 适用：小程序、后台；行业：通用；使用 1 次，最近 2026-10-26
- 要点：先定义主题色系统再画页面：主色（官方色板一列 10 阶：品牌、悬停、按下、浅底）、营销辅色（邻近色的文字阶与浅底阶）、中性灰阶与页面底（浅白或极浅灰）、状态色；按钮、标签、图标底块、卡片都从这套色取，只用纯色，不另造渐变与纹理。
- 示例：健身：青绿主色、琥珀强调、珊瑚、天蓝、紫罗兰辅助

### PAT-055 动效按导航关系选择
- 适用：小程序、后台；行业：通用；使用 1 次，最近 2026-10-26
- 要点：进入二级页右滑入覆盖、返回右滑出，标签切换淡入不滑动，弹层只在打开时播放，模块收起，数据变化行闪烁与数字计数；可打断，减少动态时只淡入
- 依据：[转场动效模式与时长](https://github.com/material-components/material-components-android/blob/master/docs/theming/Motion.md)

### PAT-086 功能分四类再决定位置：核心、信息、营销、辅助
- 适用：小程序、后台、网页；行业：通用；使用 1 次，最近 2026-10-27
- 要点：用四个问题判断：用户主要来完成什么、多久用一次、去掉它产品还成立吗、有没有时间库存人群限制。核心放标签或首屏固定并用主色、不可隐藏；信息紧跟核心、中性表达；营销排在核心之后、首屏不超过 2 个、一个活动一个位置、结束或领完自动收起；辅助进我的或详情
- 来源：用户反馈：首页太乱、按钮功能不清晰，要求区分核心功能与营销功能
- 健身房落地：首页 = 门店卡（固定）→ 门店公告、实时客流 → 新人礼券、每日抽奖；去掉宫格、轮播、热门会员卡、门店环境与设施模块
- 依据：[广告盲区研究](https://www.nngroup.com/articles/banner-blindness-old-and-new-findings/)；[首页运营位分级](https://www.woshipm.com/operate/3393101.html)

### PAT-111 会员权限按菜单分组
- 适用：后台；行业：健身房；使用 1 次，最近 2026-10-27
- 要点：员工权限编辑按菜单分组展示（会员管理、订单与收银、卡包商品、营销活动、门禁与设备、门店与内容、数据与员工），每组内勾选具体权限；切换岗位只是带入推荐权限，可再逐项调整；只有主管理员拥有的权限（退款、注销删除会员）显示为禁用并标注原因。

### PAT-132 控件自身说明用途，不加旁注
- 适用：后台、小程序；行业：通用；使用 1 次，最近 2026-10-27
- 要点：搜索框、筛选、按钮旁不放说明文字或字段标签，用占位文字、图标与无障碍名称；表单字段只留短标签，不加帮助说明句，规则冲突时给错误提示。
- 反例：搜索框上方“订单号或用户”、占位“输入后按查询”

### PAT-135 给老板看的架构图要围绕功能讲数据流
- 适用：网页；行业：企业服务、财务；使用 1 次，最近 2026-10-27
- 要点：纯技术分层（七层加一期二期色块）老板看不懂。改成三段：系统分层加每个外部系统的读取和写回；功能之间的连线流转图，连线上标数据名；每个功能一张卡，按需要的数据（带来源系统标签）、处理流程（谁做，智能体步骤用辅色）、产出与去向三栏排
- 检查脚本：标题里出现“数据来源”会被 check_document 判为来源元信息，改用“数据、流程与去向”

### PAT-139 配置闭环：小程序内容都能在后台维护
- 适用：后台、小程序；行业：通用；使用 1 次，最近 2026-10-27
- 要点：先列内容来源表（后台配置、系统计算、用户产生）；后台配置的每项都有新增、编辑、删除或停用、排序、显隐；图片可上传、删除、设封面、改说明、排序并标上限；小程序只读这份数据，不写死运营内容；同一内容一份数据（新人礼券引用优惠券）。
- 反例：相册写死、设施只能开关、公告须知不可改、礼券与优惠券两份数据、首页最高奖品写死
- 测试：后台修改后到小程序对应位置核对
- 依据：[上传组件](https://ant.design/components/upload-cn)；[拖放设计指南](https://www.nngroup.com/articles/drag-drop)

### PAT-152 规范分层：通用在上、分端在下，同名七层
- 适用：小程序、后台、智能体、网站；行业：通用；使用 1 次，最近 2026-10-28
- 要点：设计规范按七层从上到下：设计架构 → 功能架构 → 信息架构与导航 → 页面与版式 → 组件 → 视觉基础 → 文案。通用设计规范写四个端共用的标准，每层末尾一张“分端细则”表；网页管理后台、小程序、智能体、网站四个分端规范用同样的七层标题，只写各端细则。分端规范只能收紧通用规则，不能放宽；没写到的按通用规则。设计时上一层定了才做下一层。
- 反例：网站规范允许主行动在一页出现三次，与通用规范“同一目的地一个入口”冲突
- 改法：改为首屏一个主行动，滚出视区后由吸顶栏承接，同一时刻只出现一个
- 依据：[原子设计方法 第二章](https://atomicdesign.bradfrost.com/chapter-2)

### PAT-161 智能体产品的驾驶舱可以只汇总智能体产出
- 适用：后台；行业：B2B获客；使用 1 次，最近 2026-10-28
- 要点：获客智能体的概览按价值排列：新增线索、高分线索、已成交 → 新增企业、已读公告 → 研究任务；等待处理与失败任务、站点成功率放在风险与异常，等待处理大于 0 时顶部出现可关闭预警。

- 适用：通用；行业：通用；使用 1 次，最近 2026-10-26

### PAT-047 本地生图服务的使用经验
- 适用：小程序、后台；行业：通用；使用 1 次，最近 2026-10-26

- 来源：001-健身房小程序和后台系统 生成 20 余张图的实测

### PAT-056 表单失焦校验不要重绘整表

### PAT-097 写规范前先用 LuzCrawl 做业务与规范两类调研

- 依据：[超级猩猩会员与私域拆解](https://www.woshipm.com/share/5956745.html)

### PAT-112 LuzCrawl 本地请求窗口会用尽
