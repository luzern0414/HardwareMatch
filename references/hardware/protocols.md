# 通信方式与协议

选型的核心是"每两台设备之间用什么连、用什么说话"。本页从物理层到云端逐层说明，最后给出"设备如何连到后台系统"的标准接入模式。系统连接图里的每一条线都要标：**介质/接口 + 协议 + 方向**（例：`RJ45 · HTTP 事件推送 · 人脸机→云`）。

## 1 物理层与信号

| 名称 | 是什么 | 线缆与距离 | 典型用途 | 注意 |
|---|---|---|---|---|
| 干接点（Dry contact） | 无源开关量，只有"通/断" | 2 芯，≤100 m | 出门按钮、门磁、报警按钮、闸机开闸信号、烟感报警输出 | 不带电，靠接收端检测；常开 NO / 常闭 NC |
| 继电器输出 NO/COM/NC | 设备内部触点，控制外部回路 | 按负载选线径 | 人脸机/控制器驱动电锁、网络继电器驱动接触器 | 触点容量有限（常 2–10 A），大负载用接触器 |
| 韦根 Wiegand 26/34 | 读头→控制器的单向卡号脉冲（D0/D1 两根数据线） | 6–8 芯，≤80 m | 读卡器、人脸机作读头、扫码读头 | 只能传 26/34 位数字；**传不了二维码原文**；无加密 |
| RS485 | 差分串行总线，一主多从 | 双绞线 A/B，≤1200 m，最多 32 节点 | 读头、锁控板、电表、温湿度、Modbus 设备 | 需终端电阻、手拉手接线，地址不冲突 |
| RS232 / TTL 串口 | 点对点串口 | ≤15 m | 扫码模组、调试 | — |
| 以太网 RJ45 | TCP/IP 网络 | 超五类/六类网线，≤100 m | 人脸机、摄像机、控制器、网关 | 超过 100 m 用交换机中继或光纤 |
| PoE（802.3af/at/bt） | 网线同时供电 | 同以太网 | 摄像机、AP、音柱、部分人脸机 | 计算总功率预算；非标 PoE（24V 被动）不能混用 |
| 4G Cat.1 / Cat.4 | 蜂窝网络 | 物联网卡 | DTU、智能空开、储物柜、备份链路 | 物联网卡要定向/实名，流量池；信号弱处外置天线 |
| NB-IoT | 低功耗广域 | — | 烟感、水浸、电池设备 | 下行延迟高，不能用于开门 |
| WiFi 2.4G | 局域无线 | — | ESP32、红外遥控、智能插座 | 设备多时信道拥堵，关键设备优先有线 |
| Zigbee 3.0 | 低功耗 Mesh | 需网关 | 门磁、人体、温湿度、开关 | 经网关接入，网关再上云 |
| 蓝牙 BLE | 近场 | — | 智能门锁、体测仪、蓝牙开门 | 小程序可直连 BLE 开门作为兜底方式 |
| 红外 IR | 遥控码 | 视距 | 空调、电视 | 单向，无状态反馈 |

## 2 应用层协议

| 协议 | 模式 | 用在哪 | 要点 |
|---|---|---|---|
| **MQTT** | 发布/订阅，设备长连接 Broker | 自研设备、网络继电器、DTU、边缘网关→云 | 低带宽、支持离线消息与 QoS；主题按 `store/{店}/device/{id}/event|cmd|ack` 规划；TLS + 每设备独立凭证；Broker：EMQX、阿里云物联网平台、腾讯云 IoT Explorer、华为云 IoTDA |
| **HTTP/HTTPS 回调** | 设备主动 POST 事件；服务器返回指令 | 联网人脸机、扫码一体机 | 设备配置"服务器地址"；服务器必须在超时内（常 1–3 s）应答；用 HTTPS + 签名 |
| **WebSocket** | 设备与服务器双向长连接 | 部分人脸机云平台、可视对讲 | 支持服务器主动下发 |
| **海康 ISAPI** | 设备 HTTP REST 接口（XML/JSON） | 海康人脸机、摄像机、NVR | 人员下发 `/ISAPI/AccessControl/UserInfo/Record`、远程开门 `/ISAPI/AccessControl/RemoteControl/door/1`、事件"报警主机"推送；需设备在可达网络或走 ISUP（EHome）反向注册到平台 |
| **海康 ISUP（原 EHome）/ 大华主动注册** | 设备主动注册到平台的私有协议 | 设备在 NAT 后、平台在云 | 云端部署接入服务（或用厂商开放平台） |
| **厂商 SDK** | DLL/SO 库，内网直连设备 | 门店边缘网关 | 海康 HCNetSDK、大华 NetSDK、中控 PullSDK；需 Windows/Linux 主机 |
| **ONVIF** | 摄像机通用标准（发现、PTZ、取流地址、事件） | 不同品牌 IPC ↔ NVR | 只保证基本互通，智能事件常用私有协议 |
| **RTSP / RTP** | 实时视频流 | NVR、流媒体服务器拉流 | 浏览器不能直接播，需要转 WebRTC/HLS/HTTP-FLV（ZLMediaKit、SRS） |
| **GB/T 28181** | 国标视频联网，SIP 信令 + RTP 流 | 摄像机/NVR → 云视频平台 | 设备主动注册，适合跨公网多门店看视频；WVP-GB28181-pro + ZLMediaKit 是常见开源组合 |
| **Modbus RTU / TCP** | 主从轮询寄存器 | 电表、温湿度、IO 模块、PLC | 网关轮询后转 MQTT 上云 |
| **SIP** | 语音/视频呼叫 | IP 广播、可视对讲、求助终端 | 需 SIP 服务器（FreeSWITCH、Asterisk 或厂商平台） |
| **云对云 OpenAPI** | 厂商云平台开放接口 + 事件订阅 | 海康云眸、大华云睿、萤石、涂鸦、小米 | 不用管设备网络；按设备/调用计费，受厂商限制 |
| **厂商私有 UDP/TCP** | 控制器协议 | 微耕等门禁控制器 | 要求厂商提供协议文档或 SDK |

## 3 设备连到后台的四种接入模式

选型时为每台联网设备选一种模式，并在清单的"接入方式"列写明。

### 模式 A：设备直连云（推荐自研后台）

```
设备（人脸机/扫码机/继电器/DTU） ──4G 或门店宽带── 公网 ──HTTPS/MQTT over TLS── 云端后台
```
- 设备主动出站连接，门店无需固定 IP、无需端口映射。
- 适用：支持"自定义服务器地址 + HTTP 推送/MQTT"的设备。
- 要求：设备凭证唯一、指令签名限时防重放、离线时设备按本地白名单或离线码放行。

### 模式 B：厂商云平台中转

```
设备 ── 厂商云（云眸/云睿/涂鸦） ──OpenAPI + 事件订阅── 云端后台
```
- 设备注册厂商云，后台只对接厂商 API。开发快，设备种类多时省事。
- 代价：依赖厂商、按年/按设备收费、事件延迟与能力受限、数据经第三方（人脸数据合规要评估）。

### 模式 C：门店边缘网关

```
设备 ──局域网 SDK/ISAPI/RTSP/Modbus── 边缘网关（工控盒/树莓派） ──MQTT/HTTPS── 云端后台
```
- 网关在本地对接所有设备，做协议转换、断网缓存、本地自治（断网继续按缓存白名单开门）、视频转发。
- 适用：设备协议只能内网访问（SDK、ISAPI、RTSP、Modbus）或设备数量多的门店。
- 要求：网关远程运维、看门狗、自动升级、本地数据加密。

### 模式 D：本地闭环（无网络依赖）

```
读头 ──韦根/485── 门禁控制器 ──继电器── 电锁
```
- 用于兜底：网络和云都挂时，消防出门按钮、破玻、本地卡/离线码仍能用。
- 任何方案都必须保留模式 D 的出门路径（出门永远不依赖网络）。

## 4 典型数据流（无人场馆入场）

```
会员小程序 ──HTTPS── 后台：签发 30 s 有效的签名动态码
会员出示码 → 人脸机/扫码机读取 ──HTTP POST 码串── 后台：验签 + 资格 + 容量 + 在场唯一
后台 ──HTTP 应答"开门"或 MQTT 指令── 设备继电器动作 → 磁力锁断电 → 门开
门磁/客流摄像机 ──事件── 后台：确认进入人数（>1 判定尾随 → IP 广播警告 + 值班告警）
后台 ──MQTT── 网络继电器/智能空开：首人入场开灯开空调；在场 0 人延时关闭
离场：出门按钮/出口识别 → 事件上报 → 后台结束在场记录
```

## 5 网络与安全规则

1. 设备只出站连接（MQTT 8883 / HTTPS 443），门店路由器不做端口映射。
2. 设备网、会员 WiFi、办公网 VLAN 隔离；摄像机禁止访问公网（只允许 NVR/网关访问）。
3. 每台设备独立凭证与证书，可单独吊销；修改所有默认密码（`admin/12345` 类）。
4. 开门指令带设备 ID、时间戳、随机数、签名，有效期 ≤ 10 s，设备回执确认。
5. 心跳 30–60 s；离线超过 3 个周期告警；恢复后补传离线记录。
6. 人脸特征数据存储在设备本地或私有平台，不经第三方公网传输原始照片（按《人脸识别技术应用安全管理办法》，2025-06-01 施行）。
7. 视频监控不得覆盖更衣室、淋浴间、卫生间内部；公共区域张贴监控与人脸识别提示。
