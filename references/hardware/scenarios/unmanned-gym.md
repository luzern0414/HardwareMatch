# 场景：24 小时无人健身房

选型范围见 [hardware-basics.md](../hardware-basics.md#选型范围)：消防、供电、基础网络是现场条件，只提需求。

## 1 运营逻辑（先懂生意，再选硬件）

| 维度 | 内容 |
|---|---|
| 商业模式 | 社区/写字楼底商 100–400 ㎡；月卡、次卡、时段卡、按时长计费；小程序购卡 + 美团/抖音团购核销；不推销、24 小时营业；一人远程管理多店 |
| 成本结构 | 租金、器械折旧、电费（空调照明占大头）、保洁外包、系统与硬件；**无前台、无巡场**，所以硬件承担了前台和巡场的全部职责 |
| 收入关键 | 续费率、坪效、夜间时段利用率；团课/私教预约为增值 |
| 最大风险 | ①蹭卡、借卡、尾随（一人刷多人进）②场内突发（受伤、晕倒）无人发现 ③设备离线导致会员进不去 / 出不来 ④能源浪费（无人时灯和空调常开）⑤器械或物品损坏、盗窃 ⑥人脸与监控合规 |

### 会员动线（每一步都有硬件承接）

```
小程序购卡/团购核销 → 录入人脸（单独同意）→ 到店：刷脸 / 扫动态码
→ 第一道门开（AB 门时进入缓冲区，确认只有 1 人）→ 第二道门开 → 首人入场：灯光/空调/新风自动开启
→ 扫码分配储物柜 → 训练（摄像头 + 鱼眼覆盖，求助按钮可达）→ 淋浴（可选：计时水控）
→ 退柜 → 出门（出门按钮/出口识别，结束在场）→ 最后一人离场：延时关灯关空调
```

### 店长/值班动线（远程）

```
手机后台：实时在场人数、在场名单、今日客流 → 告警推送（尾随、超时未离场、求助、门未关、设备离线、烟感）
→ 远程看视频（鱼眼全景）→ 远程喊话（IP 广播）→ 远程开门 / 远程断电 → 处置记录
```

## 2 功能 → 设备映射（必选 / 推荐 / 可选）

| 功能 | 承接设备 | 级别 | 说明 |
|---|---|---|---|
| 身份核验入场 | 人脸识别门禁一体机（带二维码） | 必选 | 人脸 + 动态二维码双通道（法规：不得把人脸作为唯一方式） |
| 门体控制 | 磁力锁 280 kg + 支架 + 门禁电源 | 必选 | 断电开，符合消防 |
| 安全出门 | 出门按钮（红外非接触） | 必选 | 接人脸机或控制器的出门输入，出门不依赖网络；紧急破玻属消防，列为现场条件 |
| 门状态 | 门磁（磁力锁带反馈款可省） | 必选 | 门未关好告警、强开告警 |
| 防尾随 | 双目客流统计摄像机（门内上方） | 必选 | 一次核验计数 >1 → 语音警告 + 告警；或 AB 门 |
| 防尾随（强） | AB 门互锁（两道门 + 2 台人脸机 + 互锁控制器）或摆闸 | 推荐（客流大、蹭卡严重时） | 缓冲区只有 1 人时才开第二道门 |
| 训练区安防 | 鱼眼全景摄像机（每 80–150 ㎡ 一台） | 必选 | 吸顶 3 m，覆盖全区，后台远程看 |
| 出入口/前台录像 | 半球/枪机 | 必选 | 门口人脸清晰录像，用于申诉与纠纷 |
| 录像存储 | PoE NVR + 监控硬盘 | 必选 | ≥30 天 |
| 求助 | SOS 一键求助按钮/可视对讲 | 必选 | 器械区、淋浴区外、门口；呼叫值班 |
| 语音提示 | IP 网络音柱/吸顶音箱 | 推荐 | 欢迎、尾随警告、闭店提醒、远程喊话 |
| 智能电控 | 网络继电器/智能断路器 + 交流接触器 | 推荐 | 首人入场开、无人延时关；分回路（照明、空调、新风、跑步机电源） |
| 空调控制 | 智能断路器（中央/柜机）或 WiFi 红外遥控（挂机） | 推荐 | 与电控联动 |
| 长时间在场/异常 | 毫米波人体存在传感器、鱼眼 AI | 可选 | 静止过久告警 |
| 储物 | 智能储物柜（扫码） | 推荐 | 入场分配，离场释放 |
| 淋浴 | 扫码计时水控 | 可选 | 防长流水 |
| 体测 | 体测仪 | 可选 | 增值 |
| 售卖 | 自助售货机 | 可选 | 饮料、蛋白棒 |
| 网络 | 现场条件：路由器、4G 备份、PoE 交换机 | — | 本方案只提网口数、PoE 功率、上行带宽、出站端口需求 |
| 边缘网关 | ARM 工控网关 | 推荐（模式 C）| 对接 NVR/人脸机 SDK、断网缓存、继电器 MQTT 桥接 |
| 供电保障 | 现场条件：门禁电源（含后备电池）、UPS | — | 本方案只提 12V 电流与 220V 点位需求；磁力锁必须断电开 |
| 消防 | 现场条件：烟感、破玻、消防联动 | — | 本方案只要求提供"火警断锁电"的联动信号接点 |

## 3 两档典型配置

| 配置 | 适用 | 入口方案 | 摄像头 | 估算硬件（不含器械、装修） |
|---|---|---|---|---|
| 标准店 | 150–300 ㎡，单入口 | 1 台人脸机 + 磁力锁 + 双目客流防尾随 | 1 半球（门口）+ 2 鱼眼 + 1 客流 | 系统硬件约 0.8–1.5 万元 |
| 增强店 | 300 ㎡ 以上或蹭卡严重 | AB 门：2 台人脸机 + 2 套磁力锁 + 互锁 | 1–2 半球 + 3 鱼眼 + 1 客流 | 系统硬件约 1.5–3 万元 |

（不含现场网络、供电、消防；价格以经验库与本次 1688/官网实测汇总为准。）

## 4 关键时序与规则

1. **入场判定在后台一次完成**：凭证有效 → 会员状态 → 有可用卡/时段 → 门店未满员 → 本人不在场 → 扣次 → 下发开门。设备只负责识别和执行，不在设备上做业务判断（离线兜底除外）。
2. **防尾随判定**：后台收到"开门成功"后开一个 5–10 s 窗口，统计客流相机"进"方向计数；>1 → 记录尾随事件、IP 广播"请每位会员单独核验"、推送值班、关联鱼眼截图。
3. **离场**：出门按钮/出口识别上报 → 结束在场；超过配置时长（如 4 h）未离场 → 告警值班，值班看鱼眼确认后人工结束。
4. **电控**：在场人数 0→1 开启照明/空调/新风；1→0 延时 10–15 分钟关闭；营业时段与夜间模式可配。
5. **离线兜底**：网络中断时人脸机按本地已同步名单放行并缓存记录，恢复后补传；出门按钮、破玻、消防联动全程本地有效。
6. **停电**：门禁电源后备电池维持人脸机 + 控制器；磁力锁断电即开（会员可离场）；UPS 维持路由器/NVR/网关上报停电告警。
7. **合规**：人脸单独同意 + 可撤回 + 二维码替代；更衣、淋浴、卫生间内部不装摄像头；入口张贴"视频监控 / 人脸识别"提示；未满 14 岁不开人脸。

## 5 选型检查要点（本场景特有）

- 人脸机：必须支持二维码 + HTTP 平台对接/远程开门 + 活体 + 宽动态；门口朝外有逆光时优先宽动态 ≥120 dB。
- 客流相机：安装在门内正上方，高度 2.2–3.5 m 区间，检测宽度覆盖门宽；确认事件可推送到后台或接入 NVR 后经网关订阅。
- 鱼眼：600 万以上；确认后台播放端矫正方式。
- 继电器/空开：控制空调、跑步机等大负载时必须经交流接触器；由持证电工施工。
- 网络：上行 ≥ 20 Mbps（远程看 2–3 路子码流）；4G 备份卡开通物联网流量。

## 7 完整系统方案（从头到尾）

写 plan.json 的 `scenario` 时以此为底稿，按门店实际增删。格式：操作 → 系统响应 ｜ 硬件 ｜ 功能 ｜ 异常。

### 7.1 开业准备（店长，一次性）

| # | 操作 → 响应 | 硬件 | 功能 | 异常 |
|---|---|---|---|---|
| 1 | 后台设置营业时段、容量、超时阈值 → 规则下发网关，断网也按此执行 | 网关 | 门店规则 | — |
| 2 | 绑定设备 → 网关发现人脸机、控制器、NVR、继电器、对讲、音柱并开始心跳 | 全部联网设备 | 设备上线 | 发现不到：查 VLAN 与设备 IP |
