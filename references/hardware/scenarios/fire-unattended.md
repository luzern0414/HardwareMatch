# 场景：动火离人（明火/灶具开着却无人看守）

定义：厨房、后厨、实验室、动火作业点等区域，**有火（明火、灶具或加热设备在工作）且区域内无人值守持续超过设定时间**时，现场提醒、推送告警，按策略联动切断。

选型范围：本场景只选"判断有火、判断有人、告警与联动执行"的系统设备。烟感、消防报警主机、灭火装置属于消防，是现场条件；燃气切断阀的安装与燃气管道改动由燃气公司或有资质单位施工，本方案只选型号并给出控制接口要求。

## 1 业务逻辑

| 维度 | 内容 |
|---|---|
| 谁在用 | 餐饮后厨、单位食堂、中央厨房、学校实验室、无人自助厨房/共享厨房、工地动火作业 |
| 背景 | 市场监管推进"明厨亮灶"，后厨视频要求可看可追溯；动火离人是后厨火灾的常见起因 |
| 要回答的问题 | 现在灶上有没有火？火边有没有人？无人多久了？谁在何时离开？告警后是否处理？ |
| 典型动作 | 无人 T1（如 3 分钟）→ 现场语音提醒；T2（如 5 分钟）→ 推送店长/值班；按策略联动关闭燃气阀或电磁炉回路；人回来自动解除 |
| 最大风险 | 误报（蒸汽、反光、红色灯光、炉灶余温）、漏报（遮挡、人站在画面外）、联动误切断影响营业、视频隐私 |

## 2 判断"有火"的方法

| 方法 | 设备 | 优点 | 注意 |
|---|---|---|---|
| AI 视频识别火焰 | 摄像机 + 火焰/动火算法（摄像机内置或边缘计算盒） | 利旧明厨亮灶摄像机 | 蒸汽、反光误报；需对准灶眼 |
| 热成像测温 | 热成像（双光）摄像机，区域温度阈值 | 不受光照影响，能区分开火/余温 | 单价高 |
| 点式温度 | 红外测温探头或热电偶贴近灶具 | 便宜、可靠 | 每灶一个，布线 |
| 能源侧 | 燃气流量信号、电磁炉回路电流互感器 | 直接反映"在用" | 需燃气/电工配合 |

## 3 判断"有人"的方法

| 方法 | 设备 | 注意 |
|---|---|---|
| AI 人形检测（同一摄像机） | 摄像机 + 算法 | 与有火判断同一画面，规则最简单；画面要覆盖操作位 |
| 毫米波人体存在传感器 | 24/60 GHz 雷达，485/Zigbee/WiFi 输出 | 静止的人也能检测；不受油烟光照影响 |
| PIR 红外 | 被动红外 | 人不动时会判无人，只作辅助 |

推荐组合：**AI 视频（火 + 人）为主，毫米波存在传感器复核"无人"**，降低误报。

## 4 功能 → 设备映射

| 功能 | 设备 | 级别 |
|---|---|---|
| 火焰/动火检测 | 带动火离人/火焰算法的 AI 摄像机，或普通摄像机 + AI 边缘计算盒 | 必选 |
| 人员在岗 | 同一画面人形检测；毫米波人体存在传感器复核 | 必选 / 推荐 |
| 现场提醒 | IP 音箱或声光报警器 | 必选 |
| 远程告警 | 后台推送（小程序订阅消息、企业微信、短信、电话） | 必选 |
| 联动切断 | 燃气紧急切断阀（控制器干接点/485 输入）、网络继电器 → 接触器切断电加热回路 | 可选（按管理策略） |
| 明厨亮灶上传 | 摄像机 → NVR → GB28181 上级平台 | 按当地监管要求 |

## 5 数据通路与规则

```
AI 摄像机/算法盒 ──事件（HTTP/ISAPI/MQTT）── 边缘网关 ──MQTT/TLS── 云端规则引擎
毫米波传感器 ──485 Modbus / Zigbee── 网关
规则：火=有 且 人=无 持续 T1 → 现场语音；持续 T2 → 推送告警并记录截图；策略允许时 → 网关下发切断指令 → 网络继电器/燃气阀控制器 → 回执
人回来或火熄灭 → 自动解除，记录处置时长
```

- 判断在边缘网关执行（断网也能现场提醒和切断），云端负责推送、记录、统计。
- 切断动作要有确认与恢复流程：切断后需人工到场复位，不能远程直接重新开启燃气。

## 6 选型检查要点

1. 算法：确认"动火离人"或"火焰检测 + 区域无人"是设备/算法盒的现成功能，事件能通过 HTTP/ISAPI/SDK 推出来。
2. 摄像机：广角覆盖全部灶位与操作位，防油污外壳或定期清洁；后厨高温高湿，确认工作温度湿度。
3. 毫米波：安装高度与探测范围覆盖操作位；输出接口与网关匹配（485/干接点/Zigbee）。
4. 切断执行：燃气阀控制器接受的信号类型（干接点常开/常闭、485）；电加热回路必须经接触器，由电工施工。
5. 误报控制：火持续时间阈值、人离开阈值可配；蒸汽区域屏蔽；告警附截图供人工复核。
