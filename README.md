# Luz System

面向中文产品的系统设计技能（Agent Skill）：把一句需求变成**一套完整、经人工批准的系统设计**，软件与硬件一起设计——从系统方案、功能清单、网页管理后台 / 小程序 / 智能体 / 网站的界面与可交互原型，到现场设备的选型、接口协议、连接图与预算。

## 能做什么

- **系统方案**：确认模块范围 → 用真实浏览器调研同类产品 → 系统架构（角色、功能、页面、动作、流程与异常、状态、外部集成、追溯）→ 系统设计网页。
- **界面设计**：按七层规范（设计架构 → 功能架构 → 信息架构与导航 → 页面与版式 → 组件 → 视觉参数 → 文案）设计四个端，分别遵循后台、小程序、智能体、网站的细则，例如后台驾驶舱按价值排序、小程序页面栈与返回、智能体的审批与接管、网站的首屏与转化。
- **可交互原型**：功能列表 + 小程序 + 后台合在一个自包含的 HTML 里，用浏览器逐页验收。
- **硬件设计**：先写清业务运转的完整流程，再把每个环节映射到设备（人脸与扫码门禁、门禁控制器、电锁、客流相机、热成像、网络继电器、边缘网关等），写明每两台设备之间的接口与协议、断网兜底和对现场的供电网络需求，并核对型号、价格与采购渠道，输出带系统连接图的选型清单。
- **质量把关**：每个阶段都有人工批准记录（含文件哈希），并有脚本校验结构、追溯和交付文件。
- **经验库**：软件侧沉淀功能、流程、组件与规则；硬件侧沉淀产品、价格样本、兼容关系、采购渠道与搜索词，下一个项目先查库。

## 典型用法

把本目录放进 Agent 的技能目录后，直接提需求，例如：

- “做一个健身房小程序和门店后台的系统设计和可交互原型。”
- “我要开一家 24 小时无人健身房，软件和硬件一起出方案。”
- “商场要统计各入口客流和在场人数，需要哪些设备、怎么接？”
- “给这个智能客服设计对话界面和审批流程。”

每个项目一个会话目录，最终只交付一个 HTML，其余过程文件放在 `raw/` 里。

## 目录结构

```text
SKILL.md          技能入口：分工、路由、规则摘要、工作顺序
WORKFLOW.md       各阶段的进入条件与停止条件
references/       规范网页 8 份（界面通用、后台、小程序、智能体、网站、功能列表、系统设计、硬件设计）、硬件知识库、会话模板、开发交接契约
experience/       软件经验库；hardware/ 为硬件经验库
examples/         无人健身房硬件方案示例
scripts/          建会话、发布、校验、经验库、硬件方案生成、测试
agents/           Agent 平台配置
```

个人联系人（手机号、微信）与第三方产品实物图只保存在本机，不进入仓库。

## 依赖

- Python 3.11 及以上；浏览器验收用到 Playwright。
- 调研依赖 [Luz-Crawl](https://github.com/luzern0414/Luz-Crawl)；视觉标准与文件检查脚本来自 [Luz-Design](https://github.com/luzern0414/Luz-Design)。
- 默认把产出写到 `D:\Codes\skill输出\Luz-System\`，可在 `scripts/new_session.py` 中修改。

## 五个技能的分工

| 技能 | 负责 |
|---|---|
| **Luz-System**（本仓库） | 系统设计：软件方案、界面与原型、硬件选型 |
| [Luz-Design](https://github.com/luzern0414/Luz-Design) | 视觉标准、海报与品牌视觉、报告与表格与 Word 等文件排版 |
| [Luz-Dev](https://github.com/luzern0414/Luz-Dev) | 后端、接口、数据库、部署与上线 |
| [Luz-Writing](https://github.com/luzern0414/Luz-Writing) | 文章、文案、协议等文字内容 |
| [Luz-Crawl](https://github.com/luzern0414/Luz-Crawl) | 真实浏览器检索与采集 |
